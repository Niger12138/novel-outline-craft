# 大纲体检：常见病症与修法

用于第 5 步（体检与回改）。先定位病症属于哪一层，再回那一层修，不要在细纲里打补丁。

---

## 一、病症对照表

| 症状 | 根因 | 该回哪层 | 修法 |
|---|---|---|---|
| 设定膨胀、名词越来越多 | L1 用设定代替事件 | L1 | 每个设定必须绑定一个具体事件；绑定不上的删掉 |
| 支线乱长 | L1 没有主引擎判定标准 | L1 | 用"这条线能否从主引擎取出"筛；不能的砍或并入主线 |
| 中段发虚（20-60% 无聊） | L3 卷内没有中点反转 | L3 | 在卷中 50% 处插入假胜利或假失败，赌注翻倍 |
| 卷末无兑付 | L3 缺卷末兑现点 | L3 | 补"卷末局面变成什么"，并回 L1 登记 |
| 主角被动、总被推着走 | L1 缺主角的主动目标 | L1 | 给主角一个他自己要达成的东西，而不是"被卷入" |
| 动机断裂 | L4 场景跳过了触发 | L4 | 补 `【目标】`，让行动的起因可见 |
| 钩子同质 | L4 章末重复同类型 | L4 | 按八类钩子轮换；连续 3 章禁用同类型 |
| 章标题像模板生成 | L4 连章同构 | L4 | 长短句、有无标点、命名角度都要错开 |
| 伏笔不收 | 台账缺失或过期 | L1/L3 | 补 `ledger.json` 的 due_chapter；回收位置写进对应卷纲 |
| 战力/数值膨胀 | L1 无上限设计 | L1 | 给体系设每卷天花板与代价，禁止单向增长 |
| 人物工具化 | L2 人物卡只有功能没诉求 | L2 | 补七问；补不满的合并进别的角色 |
| 所有人说话一个腔调 | L2 缺声线卡或声线卡撞车 | L2 | 高频词/句式/比喻域三维差异化，同场至少两维不撞 |
| 角色行为前后不一致 | L2 状态连续性没回填 | L2 | 回填身体/信息/关系/持有物四项 |
| 节奏匀速 | L4 无张力标注 | L4 | 标张力值，制造高低差 |
| 大纲全是空话没有事件 | 结构字段 AI 味（概括、升华） | 各层 | 按 `anti-ai-outline.md` 改写对照表重写该字段 |
| 大纲读起来"很像 AI 写的" | ban 词密度高、抽象钩子多 | 各层 | 跑机检清 ban 词；钩子换成具体事件 |
| 大纲与正文脱节 | 正文写作时没回改大纲 | L4→L1 | 正文中产生的既成事实，回写大纲并在改动清单注明 |
| 开篇慢热 | L1 前 3 章无真冲突 | L1 | 把第一次真冲突提到前 300 字内（番茄档位硬要求） |
| 结局与开局不咬合 | 未做倒推 | L1 | 从终章反推，逐步接回第一卷 |

### 番茄档位专属病症

| 症状 | 根因 | 该回哪层 | 修法 |
|---|---|---|---|
| 开篇铺世界观、迟迟不进冲突 | L1 前 300 字无冲突 | L1 | 冲突前置、背景后置；背景拆碎片塞进对峙间隙 |
| 章节没有爽点，或爽点白捡 | L4 未填「本章爽点」或只写"主角变强了" | L4 | 补类型 + 兑现；写清谁被打脸、谁受损、代价是什么 |
| 爽点类型连章重复，读者脱敏 | L4 爽点类型不轮换 | L4 | 每 5 章至少覆盖 3 种爽点类型 |
| 章末钩子类型连章重复 | L4 钩子设计单一 | L4 | 番茄档位要求不连 2 章重复；按八类钩子轮换 |
| 字数忽长忽短或过短 | L4 目标字数越界 | L4 | 稳定在 2000–3000，隐形底线 1800 |
| 大段心理与环境描写 | L3/L4 场景设计靠描写推进 | L4 | 情绪改由动作与对话外化；环境只写与冲突相关的两三笔 |
| 句子长、成语堆砌 | 语言习惯偏文艺 | L4 | 拆短句、口语化；清掉文青词 |
| 压抑太久不给回报 | L3 卷内节奏失衡 | L3 | 单次压抑不超 3–5 章，并写明多久开始还款 |
| 支线太多读者跟不上 | L1 复杂多线 | L1 | 番茄读者不追多线；支线点到即止 |

## 二、体检流程

1. 跑 `python scripts/check_outline.py ./项目目录 --strict`，先清机检项（章号、字段、伏笔配对、钩子重复与同构、结构层 AI 味）
2. 机检全绿后做人读体检，按上表逐条对照
3. 每条问题标出所属层级与具体位置（章号/卷号/大纲区块）
4. 按"先 L1 后 L2 后 L3"的顺序修——上层不动，下层改多少都是白改
5. 修完重跑机检，确认无新增破损

  先修 L1 第 1 条，再修 L2，再修 L3，最后处理 L4 与 AI 味
────────────────────────

## 四、回改纪律

- 只改用户指出的部分，其余一字不动
- 输出时附「改动清单：位置 / 改动 / 原因」
- 涉及已确认事实的改动，同步更新 `outline.md`、相关卷纲、细纲与 `ledger.json`
- 用户未提及但发现的问题，单列「建议项」附末尾，不擅自改动
