# 细纲（章纲）写法规范

本文件供 L4（逐章细纲）阶段使用。模板见 `assets/templates/chapter-outline-template.md`。

---

## 一、细纲的合格标准

一条合格细纲，交给任何一个写手，都应能写出与原作者预期一致的正文。

判据：细纲里没有"怎么写"，只有"写什么"。

- 合格：`张三在茶楼被认出是假身份，他当场反咬李四，把嫌疑推给对方`
- 不合格：`茶楼气氛微妙，张三内心复杂，最终他做出了决定`

---

## 二、每章必答四问

1. 主角这章想做什么
2. 谁或什么在阻止他
3. 这章结束后局面变成什么
4. 读者为什么还要看下一章

四问有一问答不上，这一章就还没设计完。

---

## 三、章的功能分类

给每章标一个功能，避免连续同功能：

| 功能 | 作用 | 注意 |
|---|---|---|
| 推进章 | 完成任务/信息 → 前进一格 | 不要连续超过 3 章 |
| 转折章 | 出现反转、真相、翻盘 | 每卷 2-4 次 |
| 收束章 | 清算前面埋的东西 | 卷末必有一次 |
| 铺垫章 | 埋线、建关系、展示新力量 | 单章内必须自带一个小回报 |
| 爽点章 | 集中兑现代偿 | 爽点要结账，写清代价 |

---

## 四、场景最小结构

每场戏必须齐备三个标记：

`【目标】` 谁想要什么 → `【阻碍】` 什么挡着 → `【变化】` 这场结束后什么变了

- 没有变化 → 删、并、压缩
- 变化太小（只是"聊了一会儿"）→ 合并进相邻场景
- 一章内通常 1-4 场；超过 5 场说明切割过碎，合并

---

## 五、钩子工程

### 八类钩子

| 类型 | 做法 |
|---|---|
| 危机 | 角色即将遭受伤害或失去 |
| 悬疑 | 抛出未解释的异常 |
| 反转 | 已知信息被推翻 |
| 信息 | 给出"读者知道而角色不知道"的新情报 |
| 情感 | 关系发生未解决的变动 |
| 时间 | 倒计时逼近 |
| 选择 | 主角被逼二选一，都有代价 |
| 生存 | 生死线上的具体处境 |

### 纪律

1. 每章必有钩子
2. 连续 3 章不得同类型
3. 每 5 章内至少覆盖 4 种类型
4. 禁止用反问句、感叹句、总结句收尾
5. 钩子要具体——写清事件，不写"留下悬念""意味深长"

写不出钩子时，通常不是钩子技巧问题，而是这一章本身没有推进。

---

## 六、伏笔埋收纪律

- 每一条伏笔有编号 `F-XXX`，登记进 `ledger.json`
- 埋点写清"读者能记住的那个具体物件/信息"，不要埋"气氛"
- 埋与收之间至少隔 5 章（太近不叫伏笔）
- 回收时给读者一个"原来如此"的确认点，哪怕只有一句
- 收笔前未回收数为 0；确需留到下一卷的，在卷纲里写明承接位置

常见错误：

- 幽灵伏笔：细纲里写"收 F-007"，但台账里从没埋过
- 死伏笔：埋了但计划回收章已过，没人管
- 一次性伏笔：埋了只用一次就扔，白白浪费读者注意力

---

## 七、字数与节奏

- 单章目标字数写阿拉伯数字，与实际写作的字数上限保持一致（一般 2500-3500）
- 章纲里标注本章的张力值 1-10，便于检查是否匀速：

| 位置 | 建议张力 |
|---|---|
| 卷首铺垫 | 3-5 |
| 卷中转 | 6-7 |
| 卷末高潮 | 9-10 |
| 高潮后余波 | 3-4 |

连续 4 章张力相同 = 节奏匀速，改。

---

## 八、细纲 → 正文的交接清单

交给正文写作技能前，确认：

- [ ] 每章 7 个字段填满
- [ ] 章号连续无缺
- [ ] 钩子无连章重复
- [ ] 台账里的伏笔埋收与细纲标注一致
- [ ] 本卷卷末兑现点在卷纲中已登记
- [ ] `python scripts/check_outline.py ./项目目录 --strict` 全绿

交接时可一并交付：`outline.md`、本卷卷纲、本卷细纲、`ledger.json`、`state.json`。
