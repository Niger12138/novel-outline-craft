# 小说大纲与细纲工坊 · Novel Outline Craft

> 把「一个点子」变成「可以直接开写、且不会写飞」的结构。

一个面向中文网文 / 长篇小说的**结构层**创作引擎。它只做一件事：把零散的点子或一段简介，逐层建成四级可直接开写的结构，并落盘为可续写、可回改的项目文件。

**它不写正文。** 正文交给 `cn-novel-craft`、`webnovel-writing`、`time-slip-throne-novel` 等创作技能；正文润色去 AI 味交给 `de-ai-flavor`。本技能负责它们上游的结构。

---

## 为什么需要它

大纲阶段最容易翻车的，不是"写得不够好"，而是：

- **中段发虚**——前二十章有劲，后面开始空转
- **支线乱长**——写着写着主线找不到了
- **卷末没东西兑**——铺了一堆，没有一句算数的兑现
- **人物像工具人**——除了推动主角剧情，自己没有任何诉求
- **AI 腔从大纲混进正文**——"命运的齿轮""意味深长"这类词一旦写进细纲，后面每一章都要被它污染

这个技能把上面每一条都变成了**可检查的字段和硬指标**，而不是"请注意质量"这种说了等于没说的提醒。

## 四级结构

| 层级 | 产物 | 回答的问题 |
|---|---|---|
| **L1 全书大纲** | `outline.md` | 这本书卖什么、引擎是什么、总共几卷 |
| **L2 人物设定** | `characters.md` | 每个人凭什么推动剧情、怎么说话、怎么变 |
| **L3 卷纲** | `volumes/第N卷-卷纲.md` | 这一卷干什么、卷内怎么起伏、卷末兑现什么 |
| **L4 逐章细纲** | `细纲/第N卷-细纲.md` | 每一章写什么、谁挡路、本章变化、章末钩子、埋收哪条伏笔 |

贯穿全层还有两项约束：**结构层去 AI 味**，以及一组可切换的**风格档位**（`standard` / `fanqie`）。

### 五条硬规矩

1. **不越界**——不产出正文段落，做完结构交回正文技能
2. **不跳级**——上一级未确认，不展开下一级
3. **下游不反推上游**——细纲写不下去，说明问题在卷纲 / 人物设定 / 全书大纲，回上游改，不在细纲打补丁
4. **每个节点必须能兑现**——任何一节都要能落到"谁做了什么 → 局面变成什么 → 读者因此想看什么"
5. **不带 AI 腔**——结构字段里不许出现概括、升华、抽象钩子、万能形容词，不指望正文阶段再擦

## 安装

把整个目录放进你的 skills 目录即可。

```bash
# WorkBuddy / Claude Code 用户级 skills
git clone https://github.com/<your-name>/novel-outline-craft.git ~/.workbuddy/skills/novel-outline-craft

# 或手动拷贝
cp -r novel-outline-craft ~/.workbuddy/skills/
```

依赖只有 Python 3（用于 `scripts/` 下的两个脚本），无第三方包。

---

## 快速开始

### 1. 建工程

```bash
# 通用档位
python scripts/init_outline.py "《书名》" --path ./novel --volumes 4 --chapters 160

# 番茄小说档位（小白文 / 爽点密 / 钩子多）
python scripts/init_outline.py "《书名》" --path ./novel --style fanqie
```

生成的目录：

```
novel/
├── outline.md              # L1 全书大纲
├── characters.md           # L2 人物设定
├── style.json              # 风格档位（影响体检规则）
├── ledger.json             # 伏笔台账
├── volumes/                # L3 卷纲
└── 细纲/                    # L4 逐章细纲
```

### 2. 逐层填写

按 L1 → L2 → L3 → L4 顺序展开，**每级写完停在原地等确认**，确认后才往下走一层。模板在 `assets/templates/`。

可用自然语言直接驱动：

- "帮我搭个框架" / "定个故事引擎" / "设计人物" / "写人物小传"
- "分卷" / "列章纲" / "写细纲" / "规划前 20 章"
- "按番茄风格写大纲"

### 3. 体检

```bash
python scripts/check_outline.py ./novel --strict
```

体检项包括：章号连续性、每章必填字段完整性、伏笔埋收配对、钩子类型是否连章重复、章标题是否连章同构、`characters.md` 区块完整性，以及**结构字段 AI 味机检**（ban 词、抽象变化、钩子套话）。

番茄档位会读 `style.json` 自动加严：本章爽点是否填写、爽点类型是否连章重复、钩子是否连续 2 章同类型、目标字数是否越界、本章事件是否长句、是否出现文青词。

## 风格档位

开工前先确认目标平台风格，它决定整套字段与硬指标。默认 `standard`；提到番茄、小白文、爽文、下沉市场、免费平台时切 `fanqie`。

| 维度 | standard（通用） | fanqie（番茄小说） |
|---|---|---|
| 单章字数 | 2500–3500 | 2000–3000（隐形底线 1800） |
| 细纲字段 | 7 项 | 9 项（增加「开篇抓手」「本章爽点」） |
| 开篇要求 | 前 300–500 字给抓手 | 前 300 字必出冲突，第 1 章亮金手指 |
| 爽点 | 每 1–3 章一个小爽点 | 每 500–800 字一个爽点；3 章一小爽、10 章一大爽、20 章一重大反转 |
| 章末钩子 | 必有；类型不连 3 章重复 | 必有；类型不连 2 章重复；每 5 章至少 3 种 |
| 语言 | 长短句交替 | 短句为主、单句 ≤25 字、短段 |
| 额外红线 | — | 禁慢热、禁长篇世界观、禁复杂多线、禁文青词堆砌 |

换档只影响新建工程时的模板与后续体检规则，不会动已写好的内容。

## 结构层去 AI 味

结构字段里出现下面任何一种都算不合格——它会一路带进正文，且比正文更难改。

**四条结构级硬规则**

1. 每个字段必须能落到具体动作
2. "本章变化"必须命中四类之一：局面 / 权力 / 关系 / 认知
3. 钩子不许用抽象感受词
4. 禁止平均：章标题不连章同构、张力值不连章相同、钩子类型不连章重复

**ban 词（结构字段零容忍）**

```
命运的齿轮 / 宿命感 / 宿命的 / 命运的 / 不禁 / 不由自主 / 下意识
与此同时 / 内心深处 / 五味杂陈 / 意味深长 / 气氛变得 / 空气中弥漫
这一刻他终于 / 他明白了 / 不知不觉 / 林林总总 / 氤氲 / 弥漫着
```

完整的 8 种症状、改写对照表、机检与人工分工见 `references/anti-ai-outline.md`。

## 边界

**不要做**

- 不要写正文段落，不要把细纲写成正文
- 不要只有世界观和设定，没有事件和变化
- 不要在上级未确认时铺满全书章纲
- 不要用"人物要立体""故事要有灵魂""城府深沉""亦正亦邪"这类空话填大纲
- 不要保留答不满七问的工具人角色
- 不要把模仿写成照搬已有作品的开局

**默认要做**

- 多给可落地的具体事件、具体钩子、具体伏笔编号
- 多给人物一个"读者能记住的具体物件或习惯"
- 每级写完结账：这一级产出了什么、下一级要用到什么
- 拿不准用户偏好时，给 2 个方向让其选，而不是替其拍板
